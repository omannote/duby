# سكربتات الترحيل

ترحيل بيانات النظام السابق إلى مخطط النظام الجديد. المرجع الكامل:
[`docs/plan/13-migration.md`](../../docs/plan/13-migration.md).

## الترتيب

| الملف                    | ماذا يفعل                                       | يكتب؟         |
| ------------------------ | ----------------------------------------------- | ------------- |
| `attach-source.sh`       | يستعيد تفريغ الإنتاج في مخطط `legacy`           | ينشئ `legacy` |
| `01-source-adapter.sql`  | عروض `src` فوق `legacy` + خريطة الحالات         | لا            |
| `decisions.sql`          | جداول القرارات البشرية (فارغة، تُملأ يدويًا)    | جداول فارغة   |
| `00-audit-source.sql`    | تقرير عن حجم البيانات والشذوذ                   | لا            |
| `02-preflight.sql`       | يرفض التشغيل ما دام قرار أو شرط ناقصًا          | لا            |
| `03-transform-load.sql`  | التحويل والتحميل في **معاملة واحدة**            | نعم           |
| `04-migrate-storage.mjs` | نسخ الصور وحساب بصماتها وإدراج `order_photos`   | نعم           |
| `05-verify.sql`          | بوابة القبول: أعداد ومجاميع وسلامة              | لا            |
| `06-rollback.sql`        | إزالة كل ما أدخله الترحيل — **قبل الإطلاق فقط** | نعم           |

`run.sh` يشغّلها بالترتيب مع وقفة واحدة قبل أول خطوة تكتب.

## لماذا SQL لا TypeScript

خطة `13-migration.md` §5 كانت تفترض `export → transform → load` بثلاثة سكربتات
TypeScript. النظامان كلاهما على PostgreSQL، فالمسار الأقصر أدق:

- لا رحلة ذهاب وإياب عبر JSON تفقد الأنواع (`numeric` يصير `number`،
  والطوابع الزمنية تفقد المنطقة).
- التحويل والتحميل في معاملة واحدة: إمّا كامل أو لا شيء. الفصل بينهما كان
  يترك عند أول فشل قاعدةً نصف مُرحَّلة — وهي أسوأ من فارغة لأنها تبدو سليمة.
- الصور وحدها بقيت في سكربت Node، لأن Storage API ليس SQL.

## إن اختلف مخطط المصدر

`01-source-adapter.sql` هو **الملف الوحيد** الذي يُعدَّل. البقية تقرأ من `src`
ولا تعرف شيئًا عن أسماء أعمدة النظام القديم.

## القرارات البشرية

كلها في `decisions.sql`، مكانٍ واحد قابل للمراجعة. `02-preflight.sql` يرفض
التشغيل ما دام قرار واحد ناقصًا — فلا يُرحَّل شيء بافتراض صامت.

## البروفة

`pnpm test:migration` يشغّل الدورة كاملة على بيانات اختبار تحاكي كل حالة صعبة
(`tests/migration/`): فحص مسبق، تحميل، تحقق، تراجع، ثم إعادة تحميل. يفشل إن
تغيّر سلوك أي خطوة.
