# المرحلة صفر — ما يتطلب حساباتك

الكود كله جاهز في المستودع. ما تبقّى يحتاج صلاحيات على حساباتك، ولا يمكن
تنفيذه من جلسة تطوير. رتّبتُه بترتيب التنفيذ، مع ما يُتحقَّق به من كل خطوة.

> **تقدير الوقت**: ساعة إلى ساعتين إجمالًا.

---

## 0. قبل كل شيء — تأمين النظام القائم

هذه لا تنتظر المشروع الجديد. النظام الحالي يعمل في الإنتاج الآن.

- [ ] اجعل رابط محادثة ChatGPT **خاصًا**.
- [ ] دوّر كل مفتاح ظهر فيها: مفتاح `qr-admin-builder`، وأسرار واتساب وثواني.
- [ ] عطّل واحذف وظيفة `qr-admin-builder` نهائيًا.
- [ ] خذ نسخة احتياطية كاملة (قاعدة + تخزين) وتأكد من قابلية استعادتها.
- [ ] فعّل حماية كلمات المرور المسرّبة في Supabase Auth.
- [ ] تأكد أن `ALLOW_DEBUG_OTP=false`.

---

## 1. مشروعا Supabase

أنشئ **مشروعين منفصلين** — لا بيئة واحدة.

| البيئة  | الاسم المقترح     | المنطقة           |
| ------- | ----------------- | ----------------- |
| staging | `duby-staging`    | أقرب منطقة للخليج |
| الإنتاج | `duby-production` | نفس المنطقة       |

لكل مشروع سجّل: `Project Reference`, `Project URL`, `anon key`.

> **لا تستخدم مشروع النظام الحالي لأيٍّ منهما.** يبقى كما هو حتى الترحيل في
> المرحلة السابعة.

**تحقق**: من كل مشروع، `Settings → API` يعرض رابطًا ومفتاحًا مختلفين.

---

## 2. رمز وصول Supabase

`Account → Access Tokens → Generate new token` باسم `duby-ci`.

احتفظ به مرة واحدة — لن يُعرض ثانيةً.

---

## 3. مشاريع Cloudflare Pages

أنشئ **أربعة** مشاريع (اثنان لكل بيئة). أنشئها فارغة — الرفع يتم من CI، لا من
ربط مستودع.

| المشروع                 | الوجهة                  |
| ----------------------- | ----------------------- |
| `duby-staff`            | لوحة الموظفين — الإنتاج |
| `duby-customer`         | صفحة العميل — الإنتاج   |
| `duby-staff-staging`    | لوحة الموظفين — staging |
| `duby-customer-staging` | صفحة العميل — staging   |

ثم `My Profile → API Tokens → Create Token` بقالب **Edit Cloudflare Workers**،
وسجّل `Account ID` من الصفحة الرئيسية.

---

## 4. النطاقات

في Cloudflare Pages، لكل مشروع إنتاج: `Custom domains → Set up a domain`.

| النطاق           | المشروع         |
| ---------------- | --------------- |
| `app.myduby.com` | `duby-staff`    |
| `qr.myduby.com`  | `duby-customer` |

في GoDaddy أضف سجلّي `CNAME` كما يطلبهما Cloudflare.

### تحويل الروابط القديمة — لا تتخطَّ هذه

رموز QR المطبوعة في الشقق تشير إلى `myduby.com/qr/?token=…`. أضف في
`public_html/.htaccess` على GoDaddy:

```apache
RewriteEngine On
RewriteCond %{QUERY_STRING} (?:^|&)token=([^&]+)
RewriteRule ^qr/?$ https://qr.myduby.com/?t=%1 [R=301,L,QSD]
```

**تحقق**: امسح رمزًا مطبوعًا حقيقيًا بهاتفك، وتأكد أنه يصل إلى `qr.myduby.com`
محتفظًا بالرمز. بدون هذا تصبح كل الرموز الموزّعة بلا فائدة.

## 5. أسرار GitHub

`Settings → Environments` — أنشئ بيئتين: `staging` و`production`.

على بيئة `production` فعّل **Required reviewers** وأضف نفسك: هذا ما يجعل كل نشر
إنتاج يتطلب موافقتك.

لكل بيئة:

**Secrets**

| الاسم                   | القيمة                |
| ----------------------- | --------------------- |
| `SUPABASE_ACCESS_TOKEN` | رمز الخطوة 2          |
| `SUPABASE_PROJECT_REF`  | معرّف مشروع البيئة    |
| `SUPABASE_ANON_KEY`     | مفتاح anon للبيئة     |
| `CLOUDFLARE_API_TOKEN`  | رمز الخطوة 3          |
| `CLOUDFLARE_ACCOUNT_ID` | معرّف حساب Cloudflare |

**Variables**

| الاسم          | مثال (الإنتاج)             |
| -------------- | -------------------------- |
| `SUPABASE_URL` | `https://xxxx.supabase.co` |
| `STAFF_URL`    | `https://app.myduby.com`   |
| `CUSTOMER_URL` | `https://qr.myduby.com`    |

## 6. تثبيت نطاق Supabase في CSP

ملفا `_headers` يسمحان حاليًا بـ `https://*.supabase.co`. بعد معرفة معرّف كل
مشروع، ثبّته:

```
connect-src 'self' https://ABCD.supabase.co wss://ABCD.supabase.co;
```

`pnpm verify:headers` يبقى أخضر بعد التعديل.

> تُركت بصيغة عامة في الهيكل لأن المعرّف لم يكن معروفًا. تثبيتها يضيّق سطح
> الاتصال إلى مشروعك وحده.

---

## 7. النسخ الاحتياطي

- [ ] فعّل النسخ اليومي في مشروع الإنتاج (خطة Pro).
- [ ] **نفّذ اختبار استعادة واحدًا**: أنشئ مشروعًا مؤقتًا، استعد آخر نسخة،
      تحقق من العدّ، احذف المشروع. سجّل الزمن الفعلي.

نسخة احتياطية لم تُختبر استعادتها ليست نسخة احتياطية.

---

## 8. أول تشغيل كامل للخط

```bash
# 1. ادمج فرع الهيكل إلى main
#    → ينطلق CI، ثم النشر التلقائي إلى staging

# 2. تحقق من staging
open https://duby-staff-staging.pages.dev

# 3. أطلق الإنتاج
git tag v0.1.0 && git push origin v0.1.0
#    → ينتظر موافقتك، ثم ينشر

# 4. تحقق
node scripts/verify-headers.mjs https://app.myduby.com https://qr.myduby.com
```
