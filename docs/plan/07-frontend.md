# 07 — الواجهات

## 1. تطبيقان منفصلان

| | تطبيق الموظفين | صفحة العميل |
|---|---|---|
| النطاق | `app.myduby.com` | `qr.myduby.com` |
| الجمهور | موظفون مسجّلون | أي شخص يمسح رمزًا |
| المصادقة | Supabase Auth | لا — رمز QR + OTP |
| الحزمة | < 300KB مضغوطة | < 120KB مضغوطة |
| PWA | نعم — قابل للتثبيت | لا |
| الاستخدام | يومي، على الهاتف | مرة كل بضعة أيام |

**لماذا الفصل**: صفحة العميل لا يجب أن تحمل سطرًا واحدًا من كود لوحة الإدارة.
اليوم هما ملف واحد يولّده مولّد مشترك — وهو ما سمح بأن يكسر تعديلٌ في قالب
الطباعة صفحةَ التطبيق كلها.

## 3. تطبيق الموظفين

### 3.1 الشاشات

```
تسجيل الدخول
└── الإطار الرئيسي (شريط تنقل سفلي)
    ├── الطلبات          ← الشاشة الافتراضية
    │   ├── تبويب لكل عقار + تبويب «الكل»
    │   ├── تبويب «الأرشيف» (مكتمل + ملغي)
    │   ├── بطاقة الطلب
    │   ├── نافذة الاستلام / التسليم
    │   ├── نافذة الفاتورة
    │   └── تفاصيل الطلب: الخط الزمني، الصور، الدفع
    ├── العملاء
    │   ├── القائمة + البحث + التصفية
    │   ├── إنشاء عميل + QR (اختيار العقار أولًا)
    │   ├── معاينة QR وطباعته
    │   └── تفاصيل العميل + طلباته
    ├── العقارات
    ├── الصندوق              ← جديد
    │   ├── تسويتي            (كل الأدوار)
    │   │   ├── المتوقّع اليوم + قائمة التحصيلات
    │   │   └── زر «تسليم النقد» ← طريقة + مبلغ + صورة إثبات
    │   ├── بانتظار الاعتماد   (operator فأعلى) ← الشاشة الافتراضية للمدقّق
    │   │   └── نافذة الاعتماد عن بُعد مع صورة الإثبات
    │   ├── النقد غير المسلَّم  (operator فأعلى)
    │   ├── المطابقة البنكية   (operator فأعلى)
    │   └── تاريخ الفروق       (manager فأعلى)
    ├── التقارير
    └── المزيد
        ├── إعدادات الإشعارات
        ├── إدارة الموظفين   (admin)
        ├── سجل التدقيق      (admin)
        ├── رقم الإصدار
        └── تسجيل الخروج     ← ظاهر دائمًا
```

### 3.2 تخطيط الجوال الثابت

مشكلة تكررت مرتين في النظام الحالي: التطبيق يتمدد ويتشوّه عند ظهور لوحة المفاتيح.

```css
:root { --app-height: 100dvh; }

.app-shell {
  height: var(--app-height);
  display: grid;
  grid-template-rows: auto 1fr auto;  /* رأس | محتوى | تنقل */
  overflow: hidden;
  padding-bottom: env(safe-area-inset-bottom);
}
.app-content { overflow-y: auto; overscroll-behavior: contain; }
```

```ts
// visualViewport هو المقياس الصحيح — innerHeight يتغير مع لوحة المفاتيح
const vv = window.visualViewport;
const sync = () => document.documentElement.style
  .setProperty('--app-height', `${vv?.height ?? window.innerHeight}px`);
vv?.addEventListener('resize', sync);
sync();
```

قواعد ملزمة:
- `overflow: hidden` على الجذر — لا تمرير للصفحة كلها، فقط للمحتوى.
- حجم خط الحقول ≥ 16px — أقل من ذلك يجعل Safari يقرّب الصفحة تلقائيًا.
- `env(safe-area-inset-*)` في كل عنصر ثابت.
- اختبار على iPhone SE (أصغر شاشة مستهدفة) في كل إصدار.

### 3.3 النوافذ المنبثقة

عطل حقيقي: نافذة الاستلام كانت أطول من الشاشة، فاختفت أزرارها خلف شريط التنقل.

```
┌─────────────────────────┐  ← ارتفاع أقصى 85vh
│ العنوان + زر إغلاق       │     ثابت
├─────────────────────────┤
│                         │
│   محتوى قابل للتمرير      │     يتقلص
│   (كاميرا / نموذج)       │
│                         │
├─────────────────────────┤
│  [إلغاء]  [حفظ وتأكيد]   │  ← ثابت، فوق منطقة الأمان
└─────────────────────────┘
```

قواعد: التذييل **خارج** منطقة التمرير دائمًا؛ ارتفاع معاينة الكاميرا على الهاتف
≤ 40vh؛ النافذة لا تُغلق بضغط الخلفية أثناء عملية جارية.

### 3.4 ماسح QR — ثلاث طبقات

```
1. BarcodeDetector API        متاح في Chrome/Android — الأسرع
2. تحليل إطارات الفيديو       مكتبة مُجمَّعة — تغطي Safari/iOS
3. إدخال يدوي                 قارئ USB يكتب في الحقل، أو لصق الرابط
```

```ts
async function startScanner(video: HTMLVideoElement) {
  const stream = await navigator.mediaDevices.getUserMedia({
    video: { facingMode: { ideal: 'environment' },
             width: { ideal: 1280 }, height: { ideal: 720 } }
  });
  video.srcObject = stream;
  video.setAttribute('playsinline', 'true');   // إلزامي على iOS
  await video.play();
  return 'BarcodeDetector' in window ? detectorLoop(video) : frameAnalysisLoop(video);
}
```

قواعد:
- الطبقة الثانية **ليست احتياطية اختيارية** — هي المسار الوحيد على iPhone.
- إيقاف كل مسارات الكاميرا عند الإغلاق (`track.stop()`) — عدمه يترك الكاميرا مضاءة.
- عند رفض الإذن: رسالة تشرح كيف يُفعَّل من إعدادات الجهاز، وزر يفتح البديل اليدوي.
- لا تخزين لإطارات الفيديو ولا للرموز الممسوحة.
- **اختبار منع تراجع** في كل إصدار — هذا العطل عاد بعد أن حُلّ مرة.

### 3.5 زر الحالة

```
┌──────────────────────────────────────┐
│ QR-1042 · أحمد · برج النهضة · ط3 ش12  │
│ [صورة]                    4.500 ر.ع  │
│ ● قيد التنفيذ           ○ غير مدفوع  │
│                                      │
│  [ التالي: جاهز ]        [ إلغاء ]   │
└──────────────────────────────────────┘
```

- زر واحد يعرض **الوجهة** لا الحالة الحالية.
- في `confirmed`: «تأكيد الاستلام» ← يفتح نافذة QR والصورة.
- في `out_for_delivery` غير مدفوع: «تأكيد التسليم» معطّل + سبب ظاهر + بدائل.
- في `completed`: لا أزرار — شارة نهائية فقط.
- زر الإلغاء يختفي عند `completed`.

### 3.6 شاشات الصندوق

#### تسويتي — ما يراه المندوب

```
┌─ تسوية اليوم · 2026-09-16 ──────────────┐
│  المتوقّع بذمتك                          │
│         18.750 ر.ع                      │
│  من 4 تحصيلات                            │
├──────────────────────────────────────────┤
│  QR-1042 · أحمد      4.500  09:14  [×]  │
│  QR-1043 · سالم      6.250  11:02  [×]  │
│  QR-1047 · فاطمة     3.000  14:30  [×]  │
│  QR-1051 · خالد      5.000  17:45  [×]  │
├──────────────────────────────────────────┤
│        [ تسليم النقد ]                   │
└──────────────────────────────────────────┘
```

- المبلغ المتوقّع **كبير وواضح** — هو الرقم الذي يهم المندوب.
- `[×]` يلغي تحصيلًا بسبب — يختفي بعد التسليم.
- بعد التسليم: شارة «بانتظار الاعتماد» ولا أزرار.

#### نافذة التسليم

```
┌─ تسليم نقد اليوم ───────────────────────┐
│  المتوقّع: 18.750 ر.ع                    │
│                                          │
│  المبلغ المُسلَّم                         │
│  ┌────────────────────────────────────┐  │
│  │ 18.750                             │  │
│  └────────────────────────────────────┘  │
│                                          │
│  الطريقة                                 │
│  [إيداع بنكي] [مكتب] [خزنة] [تحويل]     │
│                                          │
│  رقم الإيصال (اختياري)                   │
│  ┌────────────────────────────────────┐  │
│  └────────────────────────────────────┘  │
│                                          │
│  صورة الإثبات  *إلزامية للإيداع البنكي   │
│  ┌──────────────┐                        │
│  │  [التقاط]    │                        │
│  └──────────────┘                        │
├──────────────────────────────────────────┤
│   [إلغاء]              [تسليم وتوثيق]    │
└──────────────────────────────────────────┘
```

- صورة الإثبات تمر بنفس مسار صور الطلبات: ضغط محلي، رفع مباشر، بصمة `sha256`.
- محاولة رفع إيصال مستخدم سابقًا ← رسالة صريحة: «هذا الإثبات مستخدم في تسوية سابقة».
- التذييل ثابت كباقي النوافذ.

#### تحذير النقد غير المسلَّم

يظهر في أعلى **شاشة الطلبات**، لا في شاشة الصندوق — المندوب لن يفتح الصندوق
من تلقائه:

```
┌──────────────────────────────────────────┐
│ ⚠ لديك نقد غير مسلَّم من 2026-09-15       │
│   18.750 ر.ع — سلّمه لتتمكن من التحصيل   │
└──────────────────────────────────────────┘
```

عند تجاوز الحد، زر «استلمت المبلغ نقدًا» يصبح معطّلًا بالسبب نفسه.
**التسوية المسلَّمة بانتظار الاعتماد لا تُنتج هذا التحذير ولا تحجب** — التأخير
على المدقّق لا على المندوب.

#### نافذة الاعتماد عن بُعد — `operator` فأعلى

```
┌─ تسوية: محمد · 2026-09-16 ──────────────┐
│                                          │
│  ┌────────────────────────────────────┐  │
│  │                                    │  │
│  │      صورة إيصال الإيداع            │  │
│  │      (اضغط للتكبير)                │  │
│  └────────────────────────────────────┘  │
│                                          │
│  إيداع بنكي · DEP-88421                 │
│  سُلّم: 2026-09-16 19:40  (قبل 14 ساعة) │
├──────────────────────────────────────────┤
│  المتوقّع   18.750 ر.ع                   │
│  المُعلَن    18.750 ر.ع                   │
│                                          │
│  المبلغ المؤكَّد من الإثبات               │
│  ┌────────────────────────────────────┐  │
│  │ 18.750                             │  │
│  └────────────────────────────────────┘  │
│                                          │
│  الفرق: 0.000 ر.ع  ✓ مطابق              │
├──────────────────────────────────────────┤
│   [إعادة للمندوب]      [اعتماد التسوية]  │
└──────────────────────────────────────────┘
```

- **الصورة أولًا** — هي أساس القرار في الاعتماد عن بُعد، لا الأرقام.
- الفرق يُحسب فوريًا أثناء الكتابة، بلون يميّز العجز عن الزيادة.
- خارج حد السماح ← الزر يتحول إلى «رفع للمشرف» والحالة `disputed`.
- «إعادة للمندوب» لصورة غير واضحة، بسبب مكتوب.
- تسوية المستخدم نفسه: لا يظهر زر الاعتماد، **والخادم يرفضها أيضًا**.
- الشاشة تعمل على الهاتف بنفس كفاءة سطح المكتب — المدقّق قد يعتمد من أي مكان.

### 3.7 معالجة الأخطاء

```tsx
function errorText(code: string, requestId: string) {
  const map: Record<string,string> = {
    qr_mismatch:   'الرمز الممسوح لا يخص عميل هذا الطلب',
    payment_required: 'لا يمكن التسليم قبل تسجيل الدفع',
    stale_state:   'تغيّرت حالة الطلب — سنعيد التحميل',
    photo_rejected:'تعذّر قبول الصورة، أعد الالتقاط',
    forbidden:     'ليس لديك صلاحية لهذه العملية',
    unhanded_cash: 'لديك نقد غير مسلَّم — سلّمه أولًا',
    proof_required:'هذه الطريقة تتطلب صورة إثبات التسليم',
    proof_reused:  'هذا الإثبات مستخدم في تسوية سابقة',
    self_verification: 'لا يمكنك اعتماد تسويتك — يعتمدها زميل من المشغّلين',
    settlement_locked: 'التسوية معتمدة ولا يمكن تعديلها',
  };
  return `${map[code] ?? 'حدث خطأ غير متوقع'} (${requestId.slice(0,6)})`;
}
```

قواعد:
- الخطأ يظهر **داخل** النافذة التي حدث فيها، لا خلفها.
- `request_id` مختصر معروض دائمًا — يحوّل بلاغ المستخدم إلى بحث واحد في السجل.
- `stale_state` يعيد التحميل تلقائيًا ويعرض الحالة الجديدة.
- لا رسالة عامة بلا رمز. «تعذر إتمام العملية» وحدها ممنوعة.

### 3.8 Service Worker

```js
// precache لأصول التطبيق فقط
precacheAndRoute(self.__WB_MANIFEST);

// Supabase لا يُعترض إطلاقًا — لا كاش لبيانات العملاء في المتصفح
registerRoute(({url}) => url.hostname.endsWith('.supabase.co'), new NetworkOnly());

self.skipWaiting();
clientsClaim();
```

- بصمة إصدار في اسم كل أصل ← لا تعارض نسخ.
- عند توفر تحديث: شريط «يتوفر إصدار جديد — تحديث» بضغطة واحدة.
- رقم الإصدار ظاهر في شاشة «المزيد».

## 4. صفحة العميل

### 4.1 الخطوات

```
1. جارٍ التحقق من الرمز
2. إدخال البيانات        (غير مكتمل فقط: الاسم، الهاتف، الطابق، الشقة)
3. رمز التحقق            (6 خانات، عدّاد، إعادة إرسال بعد 60 ثانية)
4. تصوير الطلب           (التقاط / اختيار، معاينة، إعادة)
5. تم                    (رقم الطلب + رسالة شكر)
```

**ما لا يظهر للعميل إطلاقًا**: اسم العقار، أي قائمة عقارات، رقم عميله، أي بيانات
عميل آخر، أي معلومة تشغيلية داخلية.

### 4.2 ضغط الصورة

```ts
async function compress(file: File): Promise<Blob> {
  const bitmap = await loadImage(file);           // createImageBitmap + بديل Image
  const scale  = Math.min(1, 1600 / Math.max(bitmap.width, bitmap.height));
  const canvas = new OffscreenCanvas(bitmap.width * scale, bitmap.height * scale);
  canvas.getContext('2d')!.drawImage(bitmap, 0, 0, canvas.width, canvas.height);

  for (const q of [0.8, 0.7, 0.6, 0.5]) {         // هبوط تدريجي حتى الحجم الهدف
    const blob = await canvas.convertToBlob({ type: 'image/jpeg', quality: q });
    if (blob.size <= 1_500_000) return blob;
  }
  throw new Error('image_too_large');
}
```

بديل `Image` ضروري: بعض صور iPhone لا يعمل معها `createImageBitmap`.

### 4.3 التعامل مع ضعف الشبكة

- رفع الصورة: إعادة محاولة تلقائية مرتين بتراجع، ثم زر يدوي.
- رمز الإرسال صالح 15 دقيقة ← فشل الصورة لا يستلزم OTP جديدًا.
- مؤشر تقدم صريح أثناء الرفع.
- الأزرار تُقفل أثناء التنفيذ ← لا إرسال مزدوج.

### الحالات ولونها

| الحالة | اللون |
|---|---|
| جديد | رمادي |
| مؤكد | أزرق |
| تم الاستلام | نيلي |
| قيد التنفيذ | كهرماني |

| خرج للتوصيل | بنفسجي |
| مكتمل | أخضر |
| ملغي | أحمر |

اللون لا يحمل المعنى وحده — كل شارة تحمل نصًّا عربيًا أيضًا.

### قواعد

- RTL أولًا: `dir="rtl"` مع خصائص منطقية (`margin-inline-start`) لا اتجاهية.
- خط عربي واضح، مُستضاف ذاتيًا (لا Google Fonts — يخالف CSP الصارم).
- مساحة اللمس ≥ 44×44px.
- تباين ≥ 4.5:1.
- أربع حالات لكل شاشة: تحميل، فارغ، خطأ، نجاح — لا شاشة بيضاء أبدًا.

### إمكانية الوصول

- عناصر HTML دلالية؛ `aria-label` لكل زر أيقوني.
- بؤرة مرئية دائمًا؛ تنقل كامل بلوحة المفاتيح.
- النوافذ تحبس البؤرة وتعيدها عند الإغلاق.
- `aria-live` للنتائج والأخطاء.
- احترام `prefers-reduced-motion`.
